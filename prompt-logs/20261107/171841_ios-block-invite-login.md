## 서버 연결 (API 세션 `aea7882`)
- 새 파일 `App/API/SafetyAPI.swift`
- **차단:** `POST /v1/blocks`에 `line_id`·`star_id`·`nebula_id` 중 하나만 보낸다.
  - 75 다른 이의 별은 성운 안의 별이라 서버에 따로 공유 id가 없다. 그래서 그 성운(`nebula_id`)의 주인을 차단한다.
  - 차단하면 광장을 다시 불러온다. 서버가 그 사람 것을 양쪽 모두에서 뺀다.
- **차단 목록(87-3):** 로그인 정보를 새로 받을 때와 87-3을 열 때 `GET /v1/blocks`로 불러온다. 행은 source와 created_at을 쓴다. 차단 풀기는 `DELETE /v1/blocks/{id}`다.
- **신고**
  - 별빛 한 줄: `POST /v1/plaza/lines/{id}/report {reason, block}`
  - 별·성운: `POST /v1/plaza/{star|nebula}/{id}/report {reason, block}`
  - 75·73의 신고는 그 성운으로 보낸다.
  - 응답의 `blocked`가 true면 차단 목록을 다시 불러온다. 별·성운 신고 뒤에는 광장도 다시 불러온다.
  - 기존 `reportLine`은 `reportLive`로 바꿨다.
- **초대 계정 로그인:** `POST /v1/auth/invite {login, password}`. 응답은 Apple 로그인과 같은 세션이고, 이후 흐름(동의 → 11)도 같다.
  - 401 invalid_credentials면 시트에 빨간 안내를 띄운다.
  - 429 같은 다른 오류는 공통 처리로 넘긴다.
- **로그아웃:** 실제 API 모드에서 로그아웃하면 기기의 차단 목록도 지운다.

## 확인 (개발 서버, curl)
- 초대 계정 로그인에 틀린 비밀번호를 넣으면 401 invalid_credentials가 온다.
- ios-sim-test 계정으로 성운 하나의 주인을 차단했다.
  - 광장 성운이 4개에서 1개로 줄었다. 그 사람의 성운 3개가 사라졌다.
  - `GET /v1/blocks`에 source "nebula"로 나온다.
  - 차단을 풀자(204) 다시 4개가 됐다.
- 날짜(마이크로초 포함)는 앱의 날짜 해석이 이미 받아들인다.
