# 환불 정책 문구와 28 충전 동의 (2026-11-07)

- 요청: "이대로 진행을 하되, 환불되는 금액을 거두었을 때 잔액이 0 아래로 떨어지면 환불이 되지 않도록 해야 해."
- 정책은 Figma 세션이 전해 준 사용자 결정(46·28 최신)을 따른다.
  - 구매 후 7일 이내에, 그 결제로 받은 코인을 다 거둬도 잔액이 0 이상일 때만 환불한다.
  - 그래도 앱 스토어가 환불하면, 남은 코인만 거두고 잔액은 0 아래로 내려가지 않는다.

## 서버 (API DEV Session 확인, server main a1a72cd)
- Apple 환불 요청(CONSUMPTION_REQUEST)에 이렇게 답한다.
  - 7일 이내이고 "잔액 − 그 결제로 받은 코인 ≥ 0"이면 GRANT_FULL, 아니면 DECLINE
  - 사용 비율을 함께 보낸다.
- 그래도 Apple이 환불하면 잔액까지만 거둔다. DB에 coins >= 0 제약이 있다.
- 거둔 양이 0인 환불 행은 코인 내역에서 숨긴다.
- 앱에서 할 일은 충전 요청에 `consumption_consent: true`를 보내는 것뿐이다(3단계 코인 연동 때).

- **28 코인 충전 (Figma 16:808, 28-1 304:13539)**
  - 상품 목록 아래에 안내 문구를 넣었다(가운데 정렬, caption, textTertiary): "충전한 코인만큼 남아 있을 때만 환불할 수 있어요. / 환불을 요청하면 코인 사용 내역이 앱 스토어에 전달돼요."
  - 그 아래 필수 체크 "(필수) 결제·환불 정책에 동의해요"를 넣었다. 가입 동의와 같은 `CheckboxRow`이고, ›를 누르면 46이 열린다.
  - "결제·환불 정책 보기" 링크를 지웠다.
  - 체크 전에는 "충전하기"가 비활성이다. 충전할 때마다 다시 체크한다.

## 확인하지 않은 것
- 체크한 뒤 버튼이 켜지는 모습(28-1)은 탭을 할 수 없어 보지 못했다.
- 코인은 아직 목업이다.
  - 실제 API 모드에서 `/v1/me`가 코인 값을 덮어쓰는데, 목업 모드와 같은 저장값을 쓴다. 그래서 목업 모드에도 그 값이 남는다. 이번에 0개로 보인 이유다.
  - 3단계에서 코인을 서버로 옮길 때 정리한다.
